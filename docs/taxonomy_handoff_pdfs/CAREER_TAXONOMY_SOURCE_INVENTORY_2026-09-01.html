Audience: academic reviewer, product reviewer, and the next maintainer
Purpose: identify the authoritative source inputs, the repository's derived artifacts, and the currently implemented subject-matching behavior before the content and SQL release gates are frozen.

This inventory separates three claims that must not be confused:

  1. a source exists and can be located;
  2. the source says a particular fact; and
  3. Sifter applies a documented rule to use that fact in a mapping or display.

A source URL or a file name alone proves only the first claim.

2. Domain, subgroup, and role derivation

The derivation is layered rather than a claim that one source generated every name:

ISIC activity context
  -> source-library domain identity and boundary
  -> ISCO occupational-function anchors
  -> ESCO normalized occupations and skills
  -> O*NET/ILO/WEF task, preparation, and trend enrichment
  -> Nigerian sources for local terminology, regulation, credentials, and demand
  -> Sifter domain/subgroup/role display record

The source audit currently records:

Layer Current audited scope Important interpretation
Domain records 168 total; 160 visible D001-D166 trace to the supplied library; D167-D168 are later curated additions
Domain label classes 7 exact source terms; 159 source-supported umbrellas; 2 curated additions Practitioner-facing labels are not claimed to be verbatim official classification labels
Full subgroup provenance 555/555 The full taxonomy retains provenance; visible product scope is 542
Visible subgroup context 542/542 Each visible subgroup has at least one source-backed Nigerian context record
Merged roles 5,209 Source evidence may be exact, normalized, or source-role-only; these are not interchangeable claims
Visible role context 5,093/5,093 5,089 have actual local enrichment; four are explicitly global-only

When a subgroup cannot be defended, the product uses domain -> role rather than inventing a subgroup. A role without an exact Nigerian counterpart remains global-only or otherwise bounded; global evidence is not relabelled as local demand.

The words “skill”, “competency”, “tool”, and “certification” are not treated as synonyms. A source may say that a role uses a tool or requires knowledge; that does not prove that a learner has demonstrated competence, and a certification resource does not prove that the certification is legally required in Nigeria. The display layer must preserve these distinctions.

3. Current JAMB/O-level matcher behavior

The executable behavior is in backend/routes/student_pipeline_routes.py, principally programmes_by_subjects() and _match_structured_subject_options(). The UI entry and state behavior are in src/screens/careerIntelligence/AdmissionBrowseScreen.tsx.

Three supported modes

Mode Inputs Rule applied Result meaning
JAMB-only / utme Exactly four normalized UTME subjects, including Use of English Match only typed utme option records; required subjects and one-of groups must be satisfied Subject-combination guidance for the JAMB gate, not an admission guarantee
O-level-only / olevel Five to the configured early-guidance maximum normalized O-level subjects Match only typed olevel option records; named requirements and the total credit minimum are enforced O-level programme-fit guidance without using UTME rows
Combined / combined Exactly four UTME subjects plus five to the O-level maximum Independently match UTME and O-level by the same canonical JAMB programme ID, then intersect; retain O-level gaps/status A combined view showing eligible, utme_match_olevel_gap, or utme_match_olevel_unparsed where applicable

The matcher fails closed unless the subject catalogue, structured option seed, and typed rule-record seed agree on programme ID, requirement ID, exam type, and source text. It does not turn a shared word in unparsed brochure prose into an exact match. University offerings are attached only after the canonical JAMB programme match; they add address, requirements, and notes rather than creating a different programme identity.

Worked matcher example

Suppose a typed UTME rule contains required CHEM and BIO, plus one of MATH or PHY, while its O-level rule requires ENG, BIO, MATH, and CHEM, plus one of GEO, HSC, PHY, or STAT.

JAMB-only selection:
  ENG, CHEM, BIO, PHY
  -> the UTME rule matches because CHEM and BIO are present and PHY satisfies
     the one-of group.

O-level-only selection:
  ENG, BIO, MATH, CHEM, GEO plus another subject
  -> the O-level rule matches because all named credits and the one-of group
     are present and the minimum subject count is met.

Combined selection:
  -> compute the two matches separately;
  -> keep the programme only if its same canonical JAMB programme ID occurs in
     both result sets;
  -> report any O-level missing subjects instead of flattening UTME and O-level
     into one list.

This is why the UI can say that a programme fits the UTME subjects while still showing an O-level gap. It is also why a stream changes ordering of subject choices but does not silently hide valid catalogue subjects. The independent matrix audit and tests document the same behavior in docs/manual-review/subject-selection-matrix-run-2026-08-18.md and backend/tests/test_student_pipeline_match.py.

4. Review and release interpretation

The historical CCMAS/JAMB complement audit reported 547 sufficient, 153 insufficient, and 11 missing-anchor occurrences. That was a before-state diagnostic. The current reviewed artifact covers all 711 occurrences:

Disposition Count Product meaning
Certified Nigerian curriculum link 547 Publish the relationship with exact curriculum anchors
Resolved Nigerian bridge link 163 Publish as a guided bridge, not an automatic qualification
Removed unsupported candidate 1 Keep in audit; do not seed/display as active

Therefore, the 153 were not silently erased or treated as exact matches. They were reclassified through the reviewed disposition layer. The remaining bounded states are also explicit: 220 intentional partial definitions, 135 no source-candidate records, 26 unmatched WEF signals, two ambiguous WEF signals, and four visible global-only roles. “Reviewed” means a disposition exists; it does not mean every item has an exact Nigerian counterpart, tool, certification, regulatory requirement, or local demand signal.

The population gate currently reports integrity success and permits SQL regeneration after the refreshed 5,795-row audit and review ledger were reconciled. The regenerated SQL remains a delivery artifact: it must be audited and applied only in a controlled Supabase run.
