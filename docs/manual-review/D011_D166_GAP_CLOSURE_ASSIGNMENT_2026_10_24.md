## Non-negotiable closure rules

### A. Matrix cell dispositions
- Every cell must finish as `mapped`, `not_applicable`, or `bounded_no_hit`.
- `mapped` requires a distinct, cell-specific claim with resolved source IDs, exact locator, date/version, area/horizon context, use/input/output, assumptions, limits and relationship evidence. Repeating a broad sentence across families/horizons does not map the cells.
- `not_applicable` requires a cited boundary showing why the family/horizon does not apply. ?No source found? is not not-applicable.
- `bounded_no_hit` requires actual queries over named source families, recorded sites/date/pages, negative result and explicit search boundary. It is not a shortcut for `not_assessed` or access failure.
- Type items correctly: surveys are not tools; datasets are not methods; standards are not credentials; research prototypes are not maintained production software.
- Maturity is evidence maturity, not publication year alone. Current docs do not prove an established method; a 2021 paper can still be current research.

### B. Six task-track dispositions
- Each area?s six tracks must end as `complete`, `not_applicable`, or `bounded_no_hit`. `evidence_added_gap_open` is an interim state.
- `complete` means the full stated topic focus, source families/item categories/horizons, current inventory, role/downstream context and a targeted counter-search have been assessed, with no material gap left.
- Task evidence and queries must resolve and support the stated findings. A long undifferentiated source list is not task evidence.
- Follow up material omissions found by counter-search before disposition. A track is not complete if its own counter-search reports material gaps.
- If access blocks a material claim, try an independent primary/official/credible source. If still unresolved, document the exact blocker and leave open/escalated; do not call it no-hit.

### C. Relationships and learner sequence
- Distinguish prerequisites, designs/methods, estimators/techniques, tools, data, standards and outputs. Call items alternatives only when they address the same task/output under stated conditions.
- For combinations, state which output feeds which component and under what design. Co-occurrence is not dependency.
- A technical dependency is not automatically a student learning blocker. Record learning order evidence separately; this ledger alone does not approve graph edges.
- Map roles only from actual tasks/skills/activities. Tool presence in an area does not make it a role requirement; conditional role links need explicit task conditions.
- Do not edit area/role taxonomy, role fit/routes, legacy subgroup ownership or graph data in this assignment.

### D. Source coverage before handoff
For each area, inspect relevant official standards/regulators; primary research/reviews/handbooks; maintained tools/projects; curricula/professional bodies; credible grey/practitioner/employer tasks; learning instruction; and regional/Nigerian sources where relevant. Record source versions, access, credibility, cost/licensing/data terms and geography. If a family does not apply, justify it with evidence.
